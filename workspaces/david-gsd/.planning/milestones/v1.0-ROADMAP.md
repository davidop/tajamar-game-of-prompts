# Roadmap: TaskForge

## Overview

TaskForge se construye en 4 fases (granularidad coarse) siguiendo el orden de dependencias: primero se pueden crear, listar y persistir tareas (lógica de dominio + almacenamiento + UI); después completar, filtrar y ver el progreso; luego eliminar con confirmación; y por último una pasada de accesibilidad, contrato `data-testid`, documentación y verificación de los 7 criterios de aceptación del PRD.

## Phase Details

### Phase 1: Capture & Persist Tasks

**Goal**: El estudiante puede añadir tareas válidas, verlas en una lista y recuperarlas tras recargar la página
**Mode:** mvp
**Depends on**: Nothing (first phase)
**Requirements**: TASK-01, TASK-02, TASK-03, TASK-04, TASK-05, PERS-01, PERS-02, BUILD-01
**Success Criteria** (what must be TRUE):
  1. El usuario escribe un título de 3-80 caracteres (con descripción opcional), lo envía y la tarea aparece en la lista con título, descripción y estado Pendiente
  2. Un título vacío, de solo espacios, de menos de 3 o más de 80 caracteres (sin contar espacios extremos) no crea tarea y muestra un error comprensible
  3. Con la lista vacía se ve un mensaje de estado vacío comprensible
  4. Tras recargar la página las tareas creadas siguen ahí; con `localStorage` vacío o corrupto la app arranca con lista vacía sin errores
  5. `npm run dev` arranca la app y `npm run build` termina sin errores, sin login ni llamadas remotas

### Phase 2: Complete, Filter & Progress

**Goal**: El estudiante puede marcar tareas como completadas o reabrirlas, filtrar la lista y ver su progreso
**Mode:** mvp
**Depends on**: Phase 1
**Requirements**: STAT-01, FILT-01, PROG-01, PROG-02
**Success Criteria** (what must be TRUE):
  1. El usuario marca una tarea Pendiente como Completada y la reabre sin perder título ni descripción; el cambio persiste tras recargar
  2. El usuario alterna entre Todas, Pendientes y Completadas y la lista muestra solo las tareas correspondientes sin borrar ninguna
  3. Se muestra "X%" de tareas completadas sobre el total, redondeado al entero más cercano, y se actualiza al cambiar estados
  4. Sin tareas el progreso es 0%, y cambiar de filtro no altera el porcentaje

### Phase 3: Delete with Confirmation

**Goal**: El estudiante puede eliminar tareas de forma segura mediante confirmación explícita
**Mode:** mvp
**Depends on**: Phase 2
**Requirements**: DEL-01, DEL-02
**Success Criteria** (what must be TRUE):
  1. Al pulsar eliminar aparece una confirmación explícita antes de borrar nada
  2. Confirmar elimina la tarea de la lista, del progreso y de `localStorage` (no reaparece al recargar)
  3. Cancelar deja la tarea intacta en la lista

### Phase 4: Accessibility, Contract & Docs

**Goal**: La app es utilizable con teclado y lector de pantalla, cumple el contrato de pruebas y está documentada y verificada contra el PRD
**Mode:** mvp
**Depends on**: Phase 3
**Requirements**: A11Y-01, A11Y-02, TEST-01, QUAL-01, QUAL-02
**Success Criteria** (what must be TRUE):
  1. Todo el flujo (crear, completar, filtrar, eliminar) se puede hacer solo con teclado, con foco visible, nombres accesibles y contraste legible
  2. Los errores de validación son anunciados por lectores de pantalla y el estado Pendiente/Completada se distingue por texto, no solo por color
  3. Todos los `data-testid` del contrato existen en los elementos correctos (incluidos `confirm-delete`/`cancel-delete` si hay modal)
  4. El README explica cómo instalar, arrancar y construir, y recoge los supuestos (redondeo, filtro no persistido, confirmación); no hay secretos en el código
  5. Los 7 criterios de aceptación del PRD §6 se han comprobado y pasan
