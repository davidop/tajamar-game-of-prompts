# Requirements: TaskForge

**Defined:** 2026-11-16
**Core Value:** Un estudiante puede añadir tareas y comprobar su progreso, y los datos persisten tras recargar la página.

## v1 Requirements

Fuente: PRD 1.0 (`docs/02-documento-funcional.md`), requisitos innegociables.

### Tareas (crear y listar)

- [x] **TASK-01** (RF-01): El usuario puede crear una tarea con título obligatorio de 3-80 caracteres (sin contar espacios extremos) y descripción opcional de texto libre
- [x] **TASK-02** (RF-01): Un título inválido no crea tarea y muestra un error comprensible y perceptible
- [x] **TASK-03** (RF-02): El usuario ve cada tarea con título, descripción (si existe) y estado
- [x] **TASK-04** (RF-02): Las tareas nuevas se crean en estado Pendiente
- [x] **TASK-05**: Con lista vacía se muestra un mensaje de estado vacío comprensible

### Estado y eliminación

- [x] **STAT-01** (RF-03): El usuario puede marcar una tarea Pendiente como Completada y reabrirla sin perder su contenido
- [x] **DEL-01** (RF-04): Al eliminar se solicita confirmación explícita; confirmar elimina la tarea
- [x] **DEL-02** (RF-04): Cancelar la confirmación preserva la tarea

### Filtros y progreso

- [x] **FILT-01** (RF-05): El usuario puede filtrar por Todas, Pendientes y Completadas; el filtro no borra datos
- [x] **PROG-01** (RF-07): Se muestra X% de tareas completadas sobre el total, redondeado al entero más cercano
- [x] **PROG-02** (RF-07): Sin tareas el progreso es 0%; los filtros no alteran el denominador

### Persistencia

- [x] **PERS-01** (RF-06): Toda alta, cambio de estado y eliminación persiste en `localStorage` y sobrevive a recargas
- [x] **PERS-02** (RF-06): Datos de `localStorage` ausentes o corruptos no rompen la app; no se usan datos en la nube

### Accesibilidad y contrato

- [x] **A11Y-01** (RNF-01): Todos los controles son operables por teclado y tienen nombres accesibles; foco visible y contraste legible
- [x] **A11Y-02** (RNF-01): Los mensajes de validación son perceptibles (lectores de pantalla) y el estado no depende solo del color
- [x] **TEST-01**: La UI incluye los `data-testid` del contrato: task-title, task-description, task-submit, task-item, task-toggle, task-delete, filter-all, filter-pending, filter-completed, progress-value (y confirm-delete / cancel-delete si se usa modal)

### Ejecución y calidad

- [x] **BUILD-01** (RNF-02): Aplicación estática (JS + Vite + CSS) sin login, backend, BD ni APIs remotas; `npm run dev` arranca y `npm run build` finaliza sin errores
- [x] **QUAL-01** (RNF-03): Código comprensible, sin secretos ni servicios de pago, con instrucciones de puesta en marcha en `README.md`
- [x] **QUAL-02**: Los 7 criterios de aceptación del PRD §6 se cumplen y están verificados
